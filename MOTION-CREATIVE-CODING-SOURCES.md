# Motion / Creative Coding / Computational Brand Expression Sources

Status: CURATED TECHNICAL + EXECUTION LAYER — NOT BRAND-STRATEGY AUTHORITY

Purpose: strengthen Brand Expert Core on how contemporary brand systems behave in browsers: motion, interaction, scroll, SVG, Canvas, WebGL/WebGPU, shaders, 3D, generative graphics and performance-aware implementation.

## Governing distinction

This territory has three evidence classes and they must not be collapsed:

1. **PRIMARY TECHNICAL** — official library/platform documentation that establishes what the technology can do and how it behaves.
2. **PROFESSIONAL EXPERIMENT / TUTORIAL** — expert demonstrations showing implementation patterns and creative possibilities.
3. **EXECUTION / OBSERVATION** — galleries and awards useful for discovering contemporary applications, not for proving brand effectiveness or methodology.

A visually impressive animation is not automatically strong brand expression.

## Priority A — primary technical sources

### GSAP / ScrollTrigger

Use official GSAP docs for timeline-based motion, scroll-triggered animation, scrub/pin/snap behavior, callbacks, responsive setups and synchronization.

Boundary: official docs establish technical capability. They do not establish that GSAP is the only industry-standard solution or that scroll-linked motion improves brand effectiveness.

### three.js

Use official three.js documentation/examples for WebGL/WebGPU rendering, particles, shaders/materials, post-processing, raycasting, interactive 3D and spatial behavior.

Boundary: three.js is rendering technology, not branding methodology. 3D is an expressive medium, not a default signifier of innovation.

### Lenis

Use official Lenis / Darkroom Engineering documentation for smooth-scroll orchestration and DOM/WebGL synchronization.

Boundary: smooth scrolling is a design choice, not a universal requirement. Preserve user control, accessibility, device behavior and performance.

## Priority B — professional technical laboratory

### Codrops / Tympanus

Role: HIGH-VALUE PROFESSIONAL EXPERIMENT + IMPLEMENTATION SOURCE.

Codrops currently publishes working tutorials and demos across GSAP, SVG filters/masks, scroll animation, Three.js / React Three Fiber, WebGL/WebGPU, shaders, procedural effects, 3D, grid transformations and kinetic typography.

Why it matters: examples frequently connect visible behavior to code and implementation, making Codrops useful for studying both result and mechanism.

Boundary: a Codrops experiment demonstrates possibility and craft. It does not prove appropriateness for a specific brand, universal accessibility/performance or commercial effectiveness.

## Priority C — execution / observation

### Awwwards

Use for contemporary page transitions, scroll choreography, SVG motion, WebGL/3D, kinetic type and interaction discovery.

Boundary: awards and visual novelty do not establish brand strategy quality, usability, memorability, accessibility or business effectiveness.

### CSS Design Awards

Use for discovery and comparison of current animated sites. Award status is not evidence of brand effectiveness.

### Refs.Gallery

Use tags/categories such as motion, GSAP, Three.js or animation as discovery metadata. Trace technical claims to primary sources.

### FreeFrontend

Use as CODE DISCOVERY for CSS/native animation, hover states, loaders and transitions. Contributor quality varies; browser support, accessibility and performance require independent verification.

### Utsubo and comparable Three.js roundups

Use as secondary discovery/commentary only. Trace projects to the original brand/site/studio and technical implementation before using them as evidence.

### Brand-system questions
For every technique ask:
1. What identity constant does this behavior preserve?
2. What is allowed to vary?
3. Is the motion itself recognizable or merely decorative?
4. Does the behavior encode a brand idea, system property or interaction need?
5. Could the effect be removed without losing brand meaning?
6. Does it scale across touchpoints or depend on one hero execution?

### Performance / accessibility boundaries
- reduced-motion preferences
- device capability
- progressive enhancement
- graceful fallbacks
- input modality
- browser support
- asset and GPU cost
- motion sickness / cognitive load
- interaction clarity

## Core principle

The Expert Core must learn both **how to implement motion** and **when motion is brand-bearing rather than ornamental**.

Technique literacy is necessary. It is not strategic judgment.
